## Why

复盘主线依赖 Riot API，腾讯国服不在任何 API 区域分片内，**无法服务中国玩家**。而「技能点位速查」
是纯内容型产品，不依赖任何对局 API，恰好是唯一能在中国市场落地的形态（详见
`docs/产品路线.md`）。市场信号明确：点位需求高频、易传播，但现有竞品（游民星空点位工具、瓦境
小程序等）普遍存在内容不全、交互冗长、时效性不可信的问题。

核心场景锚定为：**补位玩家在选人阶段的 60–90 秒内，拿起手机，10 秒内看到第一张点位图，
1 分钟内学会该英雄在该图的必学点位。**

差异化三支柱（区别于「点位百科」类竞品）：

1. **急救包式策展**：默认入口是「必学 5 点位」，不是全量列表。
2. **新鲜度可信**：每条点位带版本验证标签，地图改版自动标记待验证。
3. **图片优先**：标准化三图卡（站哪 → 瞄哪 → 落点效果），不靠视频。

## What Changes

- 新增 **点位内容模型**能力：地图/英雄/技能/阵营/站点/难度档/手法/版本有效性/媒体资源的
  结构化 schema；中文别名与拼音检索元数据；内容以 git 管理的 JSON + 校验脚本生产
  （后台管理平台为后续独立变更）。
- 新增 **点位速查**能力：移动端优先的「大按钮 → 地图 → 英雄 → 攻防/站点 → 必学清单 →
  三图点位卡」流程；结构化文本搜索（「亚海猎枭防B」直接解析为筛选条件，支持拼音首字母与
  社区黑话别名）；本地收藏与最近查询。
- 新增独立移动端应用工程（Taro，单代码库产出微信小程序 + H5），与现有 Web 复盘应用并存，
  复用共享内容数据层。
- 暂不纳入范围（Non-goals）：语音输入（v1.5，建立在文本解析之上）、分享卡片生成、UGC 投稿
  与审批、后台管理平台、账号体系、视频内容、复盘→点位推荐联动（阶段 2）。

## Capabilities

### New Capabilities

- `lineup-content-model`：点位内容的结构化 schema、地图/英雄/技能元数据注册表（含中文别名、
  拼音、当前图池标记）、内容校验脚本与首批样例内容。
- `lineup-quick-lookup`：移动端点位速查体验——筛选流程、必学清单、三图点位卡、结构化搜索、
  本地收藏，性能目标「打开到首图 ≤10 秒」。

### Modified Capabilities

- None。现有复盘/地图能力不受影响；地图与英雄元数据如可复用将从现有代码提取到共享层，
  实现时同步说明。

## Impact

- 新增 `apps/lineup/`（Taro 应用，weapp + h5 双构建目标）；仓库转为 pnpm workspace，
  现有 Web 应用构建方式不变。
- 新增 `packages/lineup-content/`：内容 schema（zod）、元数据注册表、点位 JSON 数据、
  校验脚本。
- 图片资源走对象存储 + CDN（国内访问优先），仓库内只存内容元数据与图片 URL。
- 验证指标（上线后 2 周）：打开→首图耗时埋点、次周留存、收藏率。
- 竞品调研（deep-research）结论落地后，允许修订本变更的策展规则与筛选维度。
