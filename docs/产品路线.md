# Valotool 产品路线备忘录

> 记录日期：2026-06-09
>
> 本文是产品方向探索备忘录，不是正式 OpenSpec 规格。若后续决定实现点位工具、小程序端或复盘建议能力，应先创建或更新对应 OpenSpec change。

## 1. 背景

上周末产品方向已重新收敛到「无畏契约比赛复盘的数据分析」。当前活跃 OpenSpec change
`import-match-and-replay-keyframes` 也正在把项目从早期的实时互动沙盘，拉回到真实对局数据驱动的关键帧复盘：

- 通过 Riot `match-details` 数据导入真实对局。
- 基于击杀、下包、拆包等关键时刻还原全员位置快照。
- 产品形态从「模拟一场假想战术」转向「解释一场真实对局」。

今天新的外部信号来自小红书：有玩家提出想做「无畏契约标点位/点位工具」，并收获一千多点赞。这说明中国玩家对低门槛、可收藏、可分享的点位查询工具存在明确兴趣。

## 2. 外部市场信号

点位工具方向不是孤立需求，已经有多个相关形态出现：

- 游民星空在 2026-06-05 上线了《无畏契约》技能点位工具，主打地图、英雄、阵营筛选和补位速查。
- 瓦境已经提供点位相关内容，并引导用户使用微信小程序查点位。
- 海外 ValoPlant、Strats.gg 等产品把 lineup、战术板、战绩追踪、地图策略等能力组合在一起。

这些信号共同说明：

- 「点位速查」是高频、容易传播、容易被普通玩家理解的入口需求。
- 微信小程序确实更贴近中国玩家的使用场景，尤其适合临场查询、收藏和转发。
- 纯点位库的竞争门槛不高，容易变成内容数量、搬运速度和社区运营的竞争。

## 3. 核心判断

不要把选择简化成「做微信小程序点位工具」或「继续做比赛复盘分析」二选一。

更合理的路线是：

```text
小程序/移动端入口
  └─ 点位速查、标点分享、补位应急、收藏
        ↓
当前 Web 核心产品
  └─ 对局复盘、关键帧、回合分析、死亡/进攻问题定位
        ↓
长期差异化
  └─ 从“我该学哪个点位”
     变成“系统告诉我这局为什么该学这个点位”
```

也就是说，点位工具适合作为流量入口和行动层，但不应替代 Valotool 的核心定位。Valotool 的长期定位应继续围绕：

**无畏契约真实对局复盘工具。点位能力是复盘之后的行动建议，也是日常训练的轻量入口。**

## 4. 两条路线对比

| 方向 | 优势 | 风险 | 更适合承担的角色 |
|---|---|---|---|
| 微信小程序点位工具 | 低门槛、高传播、适合中国玩家习惯、容易做收藏和分享 | 同质化快、内容维护成本高、长期护城河弱 | 获客入口、日常速查、用户教育 |
| Web 比赛复盘数据分析 | 差异化更强、和当前 OpenSpec 主线一致、可沉淀数据能力 | 接入门槛更高、用户理解成本更高、短期传播弱 | 核心产品、付费价值、长期壁垒 |

推荐选择：

**主线继续押比赛复盘数据分析，同时用点位工具做轻量入口。**

## 5. 推荐阶段路线

### 阶段 1：先做移动端友好的点位 H5，而不是立刻重写小程序

先在当前项目中验证点位工具的内容结构和用户路径：

- 地图筛选。
- 英雄筛选。
- 技能筛选。
- 攻防方筛选。
- 起点、落点、用途说明。
- 收藏和分享入口。

这一阶段重点不是做大社区，而是验证三个问题：

- 用户是否真的会打开查询？
- 用户是否愿意收藏和转发？
- 点位内容能否和当前地图/复盘能力复用同一套基础数据？

### 阶段 2：把点位接入复盘场景

当复盘视图能稳定展示关键帧后，点位工具应成为「复盘后的下一步」：

- 某回合下包后守包失败，推荐对应地图和下包点的守包技能点位。
- 某回合进点首杀率低，推荐默认烟、闪、侦察、清点组合。
- 某张图某个点位反复被突破，沉淀为训练清单。

这一步会让 Valotool 与普通点位库拉开差距。普通点位库回答「有哪些点位」，Valotool 应回答：

**这局暴露了什么问题，以及你下一场应该练哪个点位。**

### 阶段 3：根据验证结果决定是否做微信小程序

微信小程序适合承载：

- 点位速查。
- 收藏夹。
- 分享卡片。
- 二维码传播。
- 训练清单。

但复杂复盘、时间轴、关键帧分析、对局导入等能力仍更适合 Web 端。

因此小程序不应被视为产品本体，而应被视为中国区分发渠道和轻量入口。理想结构是：

```text
共享数据层
  ├─ 地图标定
  ├─ 英雄/技能元数据
  ├─ 点位内容
  └─ 复盘派生结果

前端形态
  ├─ Web：深度复盘、数据分析、时间轴
  └─ 小程序/H5：点位速查、收藏、分享、训练清单
```

## 6. 产品定位

短期可对外表达为：

**Valotool 是面向无畏契约玩家的复盘与点位训练工具。**

更精确的内部定位：

**以真实对局复盘为核心，用点位工具承接复盘后的练习动作，用移动端入口降低普通玩家的使用门槛。**

这避免了两个误区：

- 只做复盘：短期传播弱，用户需要较强动机才会导入对局。
- 只做点位：容易同质化，长期缺少数据壁垒。

## 7. 后续需要 OpenSpec 化的议题

如果决定推进，应拆成独立 OpenSpec change，而不是直接进入实现：

1. **点位内容模型**
   - 地图、英雄、技能、阵营、起点、落点、用途、难度、媒体资源、版本有效性。
   - 需要定义点位如何与现有地图标定和渲染系统复用。

2. **点位速查体验**
   - 移动端优先的筛选、搜索、收藏、分享路径。
   - 先做 H5 还是直接小程序，需要通过范围和数据复用方案决定。

3. **复盘到训练建议**
   - 如何从关键帧复盘结果识别可行动问题。
   - 如何把失败场景映射到推荐点位或训练清单。

4. **中国区分发形态**
   - 微信小程序、H5、公众号内容、社群分享之间的边界。
   - 小程序是否只是点位入口，还是承载账号体系和收藏数据。

## 8. 当前结论

当前不要偏离比赛复盘主线。点位工具值得做，但应被设计成：

- 一个更容易传播的入口。
- 一个更适合移动端的轻量使用场景。
- 一个承接复盘分析结果的行动层。

下一步最稳的动作是：在 OpenSpec 中提出一个轻量 change，探索「点位速查/标点工具作为复盘行动层」，并限制第一版范围，先验证内容模型、移动端查询体验和与复盘数据的连接方式。
